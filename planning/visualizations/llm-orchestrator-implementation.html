  • scripts/backfill-signals.ts (one-shot seed)
  • Correlator creates/attaches incidents

Reason Core (Act II)

Classify → Investigate → Compose → Propose
  • Anthropic Sonnet 4.6 + Haiku 4.5
  • Typed Zod tool layer + evidence ledger
  • Prompt build + cache strategy + playbooks
  • Post-validators for cite integrity

Resolve Path (Act III)

Engineer decision + dispatch
  • POST /api/initiative/:id/approve
  • manex_native adapter to product_action
  • Dispatch attempts + idempotency key
  • Closure monitor interface point

Ops & Streaming

Durable worker + SSE
  • Session event bus + replay stream
  • Worker queue for investigate sessions
  • Health endpoint + auth guards
  • Golden tests for Story 1 + Story 3

Section 3

Architecture verification snapshot

Quick completeness/correctness status of the implementation plan against current spec+architecture baseline.

Aligned

4-phase orchestrator and SSE event model

Classify/Investigate/Compose/Propose, bounded tool loop, cite validation, and session streaming are represented consistently.

Aligned

Core data objects and dispatch path

signal, incident, session, initiative, and Manex-native dispatch flow are present with typed contracts.

Gap

Contribution pipeline is under-modeled in plan execution

Spec requires full 9-domain contribution stream (3 functional + 6 stub); plan mainly focuses tool/core orchestration and does not implement this flow end-to-end.

Gap

Backfill mode 2, closure-evaluator, and external-state checks

Plan ships one-shot backfill and closure stub; incremental watermark cron and full predicate evaluation are deferred, so E2E production behavior is incomplete.

Mismatch Risk

Leadership co-sign endpoints and governance path

Approve-path gate is mentioned, but the explicit leadership co-sign endpoint and pending-cosign queue are not fully planned as first-class API routes.

Scope Constraint

Team-split dependencies block standalone completeness

Plan explicitly defers migrations/tools/UI/cron slices to teammates, so this document alone is not a fully independent blueprint for complete challenge delivery.

Verdict: the architecture is structurally correct for the orchestrator slice and demo-critical path, but not fully complete for the whole challenge-application without the deferred contribution, cron-backfill, closure, and governance slices.
