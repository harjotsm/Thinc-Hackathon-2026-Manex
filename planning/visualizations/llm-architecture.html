Act II deep-dive — the LLM pipeline inside Reason

Technical reference for building the Reason act of Resolve. Input = incident (from Listen's correlator). Output = filled 8D projection + initiative candidates with typed closure predicates (consumed by Resolve's domain agents). Everything below is LLM-layer specific — architecture.html has the three-act overview.

Positioning: This file is the single-source reference while building the agent code under app/server/agent/, app/server/tools/, app/server/prompts/, and app/server/models/. If you change a decision here, update ARCHITECTURE.md in the same PR — they must stay consistent.

Section 1

The four phases of Reason

Orchestrated pipeline, not pure ReAct. Each phase has a typed I/O contract. Tool calls are bounded; model choice is explicit.

Phase 1

Classify

in: Incident
out: Archetype + Playbook
Routes to one of five archetypes: supplier, drift, design, operator, unknown. Returns confidence + playbook snippet for Investigate.
  • 1 LLM call · no tools · Zod-validated JSON
  • Retrieves 3 nearest lesson rows as prior
Model: Haiku 4.5Budget: 2k in / 150 out
Phase 2

Investigate

in: Incident + Playbook
out: EvidenceBundle
Bounded ReAct. Plans, calls tools, reasons over results, iterates. Stops on confidence ≥ 0.75 or max 8 turns (then stalls to engineer-hint).
  • Tool calls via Anthropic SDK toolUse
  • Evidence cached by hash(tool_name, args)
  • Haiku noise-filter removes detection-bias + false positives
Model: Sonnet 4.6Budget: 18k in / 3k out
Phase 3

Compose

in: EvidenceBundle
out: Report8D + Viz
Fills 8D projection (D1–D8). Every claim cites tool_call_ids. Emits render_hint JSON for the Canvas UI.
  • Structured output via Zod schema
  • Viz picks from: pareto / timeline / fault_tree / bom_graph / image_row / kpi_card
  • DE / EN adapts to source-data language
Model: Sonnet 4.6Budget: 6k in / 2.5k out
Phase 4

Propose

in: Report8D
out: Initiative[]
N initiative candidates. Each: agent_domain, rationale, owner, deadline, typed closure_predicate, impact_estimate, confidence, evidence.
  • Owner from rework.user_id frequency
  • Closure predicate = discriminated union
  • 1–5 candidates typical; >5 → Haiku compacts
Model: Sonnet 4.6Budget: 3k in / 1.5k out

Section 3

System prompt structure & cache breakpoint strategy

~8k cached tokens up front = every turn after the first hits the cache. >80% hit rate during a demo session = >60% input-cost reduction and ~3× latency drop on cached prefix.

Anthropic messages payload layout (every phase)

Block 1
SYSTEM PROMPT: Resolve role · vocabulary (signal/incident/initiative) · Manex domain primer · 8D structure · output format rules
~2 000
Block 2
TOOL SCHEMAS: all 20+ tool definitions (Zod → JSON Schema) with examples
~3 000
Block 3
ARCHETYPE PLAYBOOKS (few-shots): supplier · drift · design · operator
~3 000
↑ cache_control: ephemeral (5 min TTL) — breakpoint here
Block 4
SESSION CONTEXT: incident summary · seed signals · retrieved lessons · archetype pick (from Classify)
~1 500
Block 5
TURN MESSAGES: previous tool_use + tool_result blocks in the ReAct loop (grows each turn)
~500–10k
Cache hit accounting during a full run: Turn 1 = cold miss on blocks 1–3 (~$0.024), warm block 4. Turns 2–8 = cache hits on blocks 1–3 (~$0.0024 each), blocks 4–5 grow. Across a 6-turn Investigate: one cold read of the 8k prefix instead of six. Caching pays for itself on turn 2.

Section 5

Tool catalog (typed, Zod-validated, bounded)

Every tool in app/server/tools/*.ts. Read tools have LIMIT 50; write tools are gated to post-approval.

🧲 Signal & Incident (Listen act — LLM reads)

Listen owns these records; LLM consumes them via typed getters.
readget_incident(incident_id: string) → Incident + Signal[]
Full incident + all correlated signals with raw payloads. Entry point for Classify.
readlist_signals_for_incident(incident_id: string) → Signal[]
Raw signal stream with source_system, captured_ts, text_payload, severity_hint.
corrfind_related_incidents(incident_id: string, top_k=5) → Incident[]
pgvector similarity over incident embeddings. For recurrence detection.

🔍 Retrieval (deterministic SQL)

Bounded Postgres queries through PostgREST / Supabase-JS.
readquery_defects(filter: DefectFilter) → Defect[]
Filter: code, section, severity, window, article_id, limit.
readtrace_batch(batch_id: string) → BatchTrace
{ parts, products, defects, claims }. Mandatory for supplier.
readbom_parts_for_product(product_id: string) → BomInstall[]
Reads v_product_bom_parts. Full supplier/batch trace.
readpareto_defect_codes(window?, article_id?) → ParetoBucket[]
Top-N codes. Emits render_hint.pareto_chart.
readtest_results_marginal(test_key?, window?) → TestResult[]
Near-limit MARGINAL values — leading-indicator retrieval.

🌐 Cross-boundary (archetype-specific joins)

Tools that encode the joins which reveal each archetype's signature.
readfield_vs_factory_gap(article_id: string) → GapReport
Anti-join: field_claim without matching defect. Mandatory for design.
readoperator_effect_analysis(user_id?, order_ids?) → OperatorPattern
Rework density per user vs. baseline. Mandatory for operator.
readrework_timeline_by_section(section_id, window) → TimelineEvent[]
Rework + defect events merged on one timeline. Essential for drift.
readweekly_quality_summary(article_id?) → WeeklySummary[]
Wrapper over v_quality_summary. Drift baseline.

🧬 Semantic · Vision · Lessons

pgvector + multimodal for free text and images.
vecsemantic_search_signals(query: string, top_k=10) → Signal[]
Cosine over all signal.embedding. Cross-source retrieval.
vecretrieve_lessons(incident_id: string, top_k=5) → Lesson[]
Network effect: past resolutions inform current hypothesis + Impact Simulator.
visclassify_defect_image(image_url: string) → ImageClassification
Sonnet 4.6 Vision. Returns { category, severity_estimate, features }.

💡 Simulation (Propose phase only)

Business-case artifact surfaced to engineer before dispatch.
simsimulate_impact(initiative: InitiativeDraft) → ImpactEstimate
Rule prior + lesson similarity. Returns { claims_avoided, eur_avoided, residual_risk, confidence }.

✍️ Write (post-approval, orchestrator calls)

LLM proposes; orchestrator writes. Never exposed in Investigate.
writecreate_initiative(payload: InitiativePayload) → { initiative_id, action_id? }
INSERT into initiative + (if Manex-native) product_action.
writeregister_closure_predicate(pred: ClosurePredicate) → { predicate_id }
Typed discriminated union persisted in team_closure_predicate.
writeemit_lesson(incident_id: string, summary: string) → { lesson_id }
Fired by closure monitor on resolved incidents. Embeds for network effect.

    props: z.record(z.unknown()),
    source_tool_call_id: z.string(),
  })),

Section 8

Grounding contract — the anti-hallucination discipline

Our single most important trust marker. 8D in front of a juror + hallucination = catastrophe.

Rule 1

Every claim cites tool_call_id

System prompt: "For every factual statement in the 8D report, include evidence: [tool_call_id, ...]. If you cannot cite a tool call, omit the claim."

Rule 2

Post-validator enforces it

Parse AgentOutput. For each evidence[] ID, verify it exists in meta.tool_calls. Unknown → reject + retry (max 1) with the validation error fed back.

Rule 3

No free-form SQL, ever

Typed tools only. Tool arg validation (Zod) before SQL execution. Invalid filter → error message back; model self-corrects.

Rule 4

Confidence < 0.6 after 4 turns → stall

Silent dead-ends get worse with more turns. Early stall → human hint → re-enter. Better than looping to max and outputting a bad report.

Rule 5

Noise-filter pre-emit

Before Compose, a Haiku pass removes detection-bias + false-positive candidates. Discarded candidates stay in meta.tool_calls for auditability.

Rule 6

Image-based claims need vision citation

If the model asserts a visual feature ("cap shows bulging"), evidence must include the classify_defect_image tool call ID.

Section 9

Guardrails & failure modes

Defensive design. The demo must not die from typical agent pitfalls.

Tool-loop cap

max_iterations = 8 per Investigate. After 8 → stall state, not output.

Output validator (Zod)

Every LLM emission through Zod. On fail: 1 retry with error feedback, then hard error.

Evidence-cite check

Every evidence[] ID must exist in meta.tool_calls. Unknown IDs → reject.

Amend budget

Engineer can amend max 2× per session. After that: full restart from Classify.

Per-phase token budget

Classify 1k · Investigate 16k · Compose 8k · Propose 4k. Overflow → Haiku summarize + retry.

Tool-arg Zod gate

Args validated before SQL execution. Invalid filter → error back to agent (self-corrects).

Rate limit / timeout

Max 5 concurrent tool calls. Tool timeout 5s. Agent total 60s.

Write gate

Write tools unavailable in Investigate. Orchestrator invokes post-approval only.

Cache TTL

Evidence 15min · embedding 24h · prompt 5min. Warm before demo.
