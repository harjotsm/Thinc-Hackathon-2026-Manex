Resolve · Merged Architecture · De.Constructors × Manex Hackathon 2026

Every voice becomes an initiative.

Closed-loop quality intelligence layer for Manex. Signals — internal production or external customer voices — are correlated into incidents, reasoned over on a live canvas, and routed as initiatives by domain agents into each system of record. 8D and FMEA fall out as projections, not primary artifacts.

Strategic framing

Three Acts — Listen · Reason · Resolve

The three pillars from the brief (Generation · Visualization · Closed-Loop) fall out as side-effects. Acts are mapped 1:1 to the three Manex slide-2 pain points.

Act I

Listen

Ingest signals from 13+ internal & external sources. Normalize into the canonical signal record. Deterministic + semantic correlator clusters them into incidents.

Answers: "Customer voices get lost, market adaptations very slow"
Act II

Reason

Incident Canvas: root-cause graph, timeline, BOM trace, contribution stream from nine stakeholder domains. Orchestrated 4-phase agent grounds every claim in a tool_call_id.

Answers: "Quality indicators lost due to high complexity"
Act III

Resolve

Five domain agents dispatch initiatives into MES / SRM / Dev-backlog / ERP / CRM. Impact Simulator shows € avoided pre-dispatch. Closure monitor verifies outcomes. Lessons embed for network effect.

Answers: "High FTE effort for the overall process"
Why this isn't a prettier 8D form-filler: Manex slide 8 says "Challenge the process itself. Do not just digitize what exists." Resolve makes 8D obsolete as a primary artifact — it becomes a regulatory-export projection of a richer underlying record. The canvas and the incident are the real product.

Section 1

The 12 load-bearing decisions

Strategic + engineering commitments. "We pick X because Y" — no hedging.

D1 · Core abstraction

Signal → Incident → Initiative (3-level)

A signal is one normalized fact. An incident is a cluster of signals worth reasoning about (the unit of UX). An initiative is the dispatched action across domain agents.

Why: the supplier story is invisible at the signal level — only a cluster of ESR near-misses + field claims makes it show up. Without Incident as first-class entity, we lose the win.
D2 · Canvas, not document

8D / FMEA / Ishikawa / Pareto are projections

The canonical workspace is the Incident Canvas. 8D view is a toggle, not a file. Export to PDF is a side-effect.

Why: Manex slide 8 explicitly forbids digitizing 8D as-is. Projection architecture lets us serve regulatory requirements without the document paradigm dominating the UX.
D3 · Agent topology

Orchestrated 4-phase pipeline inside Reason

Deterministic outer loop: Classify → Investigate → Compose → Propose. Tool calls live inside Investigate (bounded ReAct, max 8 turns).

Why: demo must be reproducible; phases make reasoning observable; retries are bounded; free-form ReAct is hackathon roulette.
D4 · Domain agents for dispatch

Five agents writing to five systems of record

Production · Supplier · R&D (real) + Logistics · Customer-Response (stubbed). Each owns its tool manifest and system prompt.

Why: Manex slide 3 literally says "implemented by agents in development, supplier management, marketing, production". Domain specialization is the brief.
D5 · Model routing

Two-tier: Sonnet 4.6 + Haiku 4.5, Opus 4.7 as fallback

Haiku: archetype classification, noise filter, summarization. Sonnet: reasoning loop, narrative, initiatives. Opus: stall recovery only.

Why: Haiku is 8× cheaper, 3× faster for deterministic tasks. ~70% inference cost savings without quality loss.
D6 · Tool layer

Typed, deterministic tools — never free-form SQL

Zod schemas per tool, bounded SQL (LIMIT 50), structured return. The LLM never calls executeSQL(string).

Why: hallucinated table names = demo abort. Typed tools = predictable latency, validated args, cacheable, grounded.
D7 · Grounding contract

Every claim cites a tool_call_id

System prompt enforces {claim, evidence: [ids]}. Post-validator checks every ID exists in the log.

Why: 8D in front of a juror + hallucination = catastrophe. Evidence traceability is our single most important trust marker.
D8 · Prompt caching

Anthropic prompt cache on the system prompt (5-min TTL)

System prompt = domain knowledge + archetype few-shots + tool schemas (~8k tokens). Cache breakpoint right after the system block.

Why: expected hit rate >80% during demo. ~60% input cost, ~3× latency reduction. Non-negotiable for live demo.
D9 · Semantic layer

pgvector for free-text only

Embed signal, complaint_text, action_text, defect.notes, and lesson. Structured queries stay SQL.

Why: RAG over structured data is an anti-pattern (SQL is more precise). RAG over free text finds supplier names and symptom phrases that no code filter catches.
D10 · Network effect via lessons

lesson embeddings retrieved per new incident

Every resolved incident writes a lesson row with embedding. New incidents pull nearest neighbors first.

Why: the platform gets smarter per plant it runs in. Defensibility story for the pitch — compounding value.
D11 · Impact Simulator (pre-dispatch)

Show € avoided before the user hits Resolve

Rule-based prior + one embedding-similarity term over lesson. Outputs projected claims avoided, cost, confidence band.

Why: judges and operators both want to see ROI before approving. This is the business-case artifact baked into UX.
D12 · Closure predicates

Programmatic, not stampable

Each initiative registers typed ClosurePredicate. Cron worker evaluates against live DB. Deadline exceeded + unsatisfied → auto-reopen.

Why: Pillar-3 scoring demands verifiable loop. "status = done" is stampable; "no SOLDER_COLD on PM-00008 for 4 weeks" is verifiable.

Section 6

Tool catalog — signatures, return types, purpose

All tools in app/server/tools/*.ts, typed via Zod, max-latency-budgeted.

🧲 Signal & Incident (new)

The Listen act. Normalize, correlate, form incidents.
writeingest_signal(payload: RawSignal) → { signal_id }
Normalizes any source into the canonical signal schema. Computes embedding, persists.
corrcorrelate_signals(signal_id: string) → { incident_id, matched_signals[] }
Runs deterministic joins + pgvector cosine. Returns existing incident to join or creates new one.
readlist_open_incidents(filter?: IncidentFilter) → Incident[]
Leadership lens portfolio feed. Supports filter by severity, plant, product family.

🔍 Retrieval (deterministic SQL)

The Investigate phase. Bounded by LIMIT 50.
readquery_defects(filter: DefectFilter) → Defect[]
Default entry point. Filter: code, section, severity, window, article.
readtrace_batch(batch_id: string) → BatchTrace
{ parts, products, defects, claims }. Mandatory for Story 1.
readbom_parts_for_product(product_id: string) → BomInstall[]
Full BOM tree with supplier/batch. Reads v_product_bom_parts.
readpareto_defect_codes(window?, article_id?) → ParetoBucket[]
Top-N defect codes + count + %. Emits render_hint.pareto_chart.
readtest_results_marginal(test_key?, window?) → TestResult[]
Leading indicator: near-limit MARGINAL values.

🌐 Cross-boundary (where stories surface)

The exact joins that make each archetype visible.
readfield_vs_factory_gap(article_id: string) → GapReport
Anti-join: field_claim without matching defect. Mandatory for Story 3.
readoperator_effect_analysis(user_id?, order_ids?) → OperatorPattern
Rework density per user vs. baseline. Mandatory for Story 4.
readrework_timeline_by_section(section_id, window) → TimelineEvent[]
Rework + defect events on one timeline per section. Essential for Story 2.
readweekly_quality_summary(article_id?) → WeeklySummary[]
Wrapper over v_quality_summary — drift baseline.

🧬 Semantic + Vision + Lessons

pgvector and multimodal, for free-text and images.
vecsemantic_search_signals(query: string, top_k=10) → Signal[]
Cosine over all signal.embedding. Cross-source retrieval.
vecretrieve_lessons(incident_id: string, top_k=5) → Lesson[]
Network effect: nearest past resolutions inform current hypothesis + Impact Simulator.
visclassify_defect_image(image_url: string) → ImageClassification
Sonnet 4.6 Vision. For operator-photo trigger.

💡 Simulation

Pre-dispatch impact projection.
simsimulate_impact(initiative: InitiativeDraft) → ImpactEstimate
Rule-based prior + lesson-embedding similarity. Returns { claims_avoided, eur_avoided, confidence }.

✍️ Write (gated, post-approval)

Not exposed inside the Investigate loop. Orchestrator calls post-approval.
writecreate_initiative(payload: InitiativePayload) → { initiative_id, action_id? }
INSERT into initiative + (if Manex-native) product_action.
writeregister_closure_predicate(pred: ClosurePredicate) → { predicate_id }
Typed union persisted in team_closure_predicate. Evaluated by cron.
writeemit_lesson(incident_id: string, summary: string) → { lesson_id }
Fired by closure monitor on resolved incidents. Embeds and indexes.

Section 9

Guardrails & failure modes

Defensive design — the demo must not die from typical agent pitfalls.

Tool-loop cap

max_iterations = 8 per Investigate phase. After 8 → stall state.

Output validator (Zod)

Every LLM emission runs through Zod. On failure: max 1 retry with error fed back.

Evidence-cite check

Every evidence[] ID must exist in meta.tool_calls. Unknown IDs → reject.

Amend budget

Engineer can amend max 2× per session. After that: full restart.

Per-phase token budget

Classify 1k · Investigate 16k · Compose 8k · Propose 4k. Overflow → Haiku summarize + retry.

Tool-arg Zod gate

Args validated before SQL execution. Invalid filter → agent error message (self-corrects).

Rate limit / timeout

Max 5 concurrent tool calls. Tool timeout 5s. Agent total 60s.

Write gate

Write tools unavailable in Investigate loop. Orchestrator invokes post-approval only.

Cache TTL

Evidence cache 15min · embedding index 24h. Warm before demo to >80% hit rate.
