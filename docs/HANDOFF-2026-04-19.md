## Architecture decisions worth knowing

- **Inbox theme signature** is `(archetype, primary_product_id ?? primary_part_number)`. `incident.dominant_entity` does NOT exist as a column.
- **Themes are derived at request time** (no `theme` table). Cheap to recompute, no migration to maintain. Caching is `revalidate: 30` on the API route.
- **Canvas + Inbox use direct Supabase fetches** in their Server Components, NOT internal HTTP calls. Faster, no `headers()` ceremony.
- **Auto-orchestrator dispatch is idempotent**. The `dispatch.ts` helper checks for a running or recently-completed session (30-min freshness) and skips if present. Manual `Run AI` button in canvas header re-runs on demand.
- **Voice pipeline reuses the existing text intake plumbing**: composes `note + transcript` into `signal.text_payload`, embeds, inserts, runs correlator. Whisper output also stored in `signal.attachments[].transcript`.
- **Title generation**: deterministic template for known archetype + entity (`"Supplier · PM-00008"`); LLM (claude-opus-4-7) for everything else with a 2-second timeout and module-cache. Used by both inbox themes and (potentially) other surfaces.
- **All commits are conventional**: `feat`/`fix`/`refactor`/`test`/`docs`. No emoji.

## How to re-run the orchestrator on all incidents (one-shot)

```bash
PORT=3000
curl -s "http://localhost:$PORT/api/incidents?page_size=50" \
  | python3 -c "import sys,json; d=json.load(sys.stdin); [print(i['incident_id']) for i in d['data']]" \
  | while read INC; do
      curl -s -X POST "http://localhost:$PORT/api/incident/$INC/investigate" -o /dev/null -w "$INC -> %{http_code}\n"
      sleep 60   # respects the 30K input tokens/min Anthropic limit
    done
```
